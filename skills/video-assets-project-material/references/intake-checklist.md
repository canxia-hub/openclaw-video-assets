# 素材入库检查清单

## 入库前

每个素材入库前确认：

- 是否属于当前项目或可复用素材。
- 是否有来源与授权说明。
- 是否能判定主类目。
- 是否已有资产文件夹 Markdown 信息卡，或是否能在入库时创建。
- 是否需要预处理、转码、裁切或降噪。
- 是否会与已有角色、场景、服装、装备、道具混淆。

不满足时留在暂存区，不进入正式 active 资产。

## 必填字段

项目：

- 中文标题。
- 中文描述。
- 阶段：验收、样片、正式制作、归档等。

资产：

- 中文标题。
- 主类目。
- 素材信息卡。
- media_type。
- 来源说明。
- 授权状态。
- 风险等级。

关键资产额外需要：

- taxonomy。
- entity link。
- annotation。
- project ref。

## 入库操作顺序

1. 上传到暂存区。
2. 判断主类目。
3. 设置中文标题。
4. 创建或更新资产文件夹的 Markdown 信息卡。
5. 核对来源与授权。
6. 确认入库。
7. 写 taxonomy。
8. 创建或复用 entity。
9. 写 annotation，并确保与信息卡一致。
10. 需要使用时再加 project ref。
11. 跑 report / continuity report。

## 各类素材最低注释

场景：

- 地点、时间、氛围、光源、连续性锚点。

角色：

- 外观锚点、表演锚点、禁改项。

服装：

- 所属角色、材质、颜色、适用场景、禁用场景。

装备：

- 所属角色或组织、功能、形态变化、交互方式。

道具：

- 剧情功能、使用者、尺寸、材质、出现镜头。

音频：

- 音频角色、关联主体、来源授权、可用范围。

风格参考：

- 只继承哪些风格信息，不继承哪些主体设定。

## 验收前检查

验收 UI 前必须确认：

- active projects 不出现英文开发测试项目。
- active assets 不出现英文 smoke/test/probe/validation 资产。
- 资产文件夹均有 素材信息卡.md 或 INFO.md。
- staging 为空，或只存在当前验收明确需要处理的中文文件。
- audit 中没有大量英文开发过程噪音。
- project_count、asset_count、ref_count 与当前验收目标一致。

## 清理规则

需要清理开发测试数据时：

1. 先备份 SQLite 数据库。
2. 先备份 visible staging/cache 文件。
3. 清理 metadata active 测试记录。
4. 新建中文空白项目或正式项目。
5. 用 authenticated RPC 复核 UI 计数。

禁止无备份删除 live 数据。
