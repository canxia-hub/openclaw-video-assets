# 素材信息卡规范

## 目的

每个资产文件夹必须配套 Markdown 信息卡，让任何 Agent 在打开素材前就能理解：

- 这个素材是什么。
- 它对应哪个角色、场景、服装、装备、道具或声音主体。
- 它的来源、授权、风险和使用边界。
- 它应该如何被项目、镜头、生成提示词、剪辑或交付环节使用。

信息卡不是可选说明，而是资产理解入口。插件数据库中的 taxonomy、entity、annotation 是结构化索引；Markdown 信息卡是面向 Agent 和人的语义说明。二者必须保持一致。

## 文件位置与命名

每个资产文件夹至少包含一个：

- 素材信息卡.md

允许兼容：

- INFO.md
- <素材文件名>.info.md

推荐资产文件夹结构：

    角色-咕咕嘎嘎-角色设计板/
    ├── 素材信息卡.md
    ├── 咕咕嘎嘎短片__角色__咕咕嘎嘎__角色设计板__20260604__v01.png
    └── previews/

如果一个文件夹收纳多个同主体素材：

    角色-咕咕嘎嘎/
    ├── 素材信息卡.md
    ├── 表情参考/
    │   ├── 素材信息卡.md
    │   └── ...
    └── 动作参考/
        ├── 素材信息卡.md
        └── ...

禁止把大量不同主体素材塞进一个文件夹，只写一张笼统信息卡。

## 与插件元数据的同步

创建或修改信息卡后，应同步检查：

- asset title 与信息卡中文名称一致。
- taxonomy 与主类目一致。
- entity canonical_name 与信息卡主体一致。
- source_rights annotation 与来源授权一致。
- project reference notes 与使用规则一致。

如果插件数据库和信息卡冲突：

1. 先判断哪个是最新确认信息。
2. 更新过期一方。
3. 在更新记录中写明变更原因。

## 最低验收门

一个资产文件夹可进入正式项目引用前，必须满足：

- 有 Markdown 信息卡。
- 信息卡主类目明确。
- 来源与授权不为空。
- 使用规则不为空。
- 角色/场景/服装/装备/道具至少有一个 entity 线索。
- 禁止用途或风险已说明。
