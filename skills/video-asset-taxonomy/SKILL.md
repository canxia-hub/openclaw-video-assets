# video-asset-taxonomy：分类注释前端可读验收

## 目的

分类、实体链接、注释和项目引用不仅要写入后端元数据，还必须能在 video-assets 工作台前端被人类理解。新前端（v1.4，2026-08-07 上线，取代旧版 GPT 单文件前端）的项目检查器会展示错误/警告徽标与资产引用列表，资产检查器展示授权/风险徽标——taxonomy 操作必须把这些前端信号当成生产质量信号。

前端验收依据：`reports/frontend-audit-2026-08-07/05-p1-acceptance.md`（检查器表面）、`09-frontend-replacement-summary.md`（新旧切换总结）。

## 前端表面映射（v1.4 工作台）

| 验收信号 | 前端位置 |
|---------|---------|
| 项目 error/warning 计数 | 项目页卡片 + 项目检查器（右侧栏）`N 错误` / `N 警告` 徽标 |
| 项目资产引用 | 项目检查器「引用资产（N）」列表（展示前 10 条） |
| 资产授权/风险 | 资产库页表格列 + 资产检查器 license/risk 徽标 |
| 分类/实体可读名 | 资产库表格标题列、画布页节点标题、Cmd+K 搜索结果 |
| 审计消息 | 审计页（/audit）action/message 列 |
| 画布引用与槽位 | 画布页（/canvas，React Flow 只读可视化）节点与连线 |

## Core Model 原则

taxonomy / entity / annotation / project ref 四者完成后，还必须能在前端形成可读解释：这个资产是什么、对应谁、为什么在这个项目里、还缺什么风险处理。

## Standard Workflow：Frontend Readability Check

完成分类、实体链接或注释后，在前端验证可读性（可用 Cmd+K 搜索资产名直达详情）：

1. 资产不应在资产库中长期显示为"未分类"或"未知媒体"，除非本轮明确就是待分类素材。
2. 角色、场景、服装、道具等关键资产应有中文 canonical name 或可读标题。
3. 注释摘要应能帮助人类理解用途、连续性约束和禁用项。
4. 项目检查器中的 warning 徽标必须被转译为明确处理动作：补 taxonomy、补 entity、补 annotation、补来源说明、补 project ref，或明确接受为测试样 warning。
5. 生成输出如被用于质量检查，应有明确分类（测试样/生成验证视频/返修输出/替换输出），而不是只显示裸版本号。

## Project Gate

项目引用关键资产前，除原有检查外：

- 前端能显示人类可读标题（资产库 / 检查器 / Cmd+K 三处一致）。
- 前端能看到分类或角色/场景/道具身份线索。
- 前端 warning 不应只留下英文技术信息；汇报时必须用中文解释影响。
- 可接受的测试样 warning 必须说明：不阻塞当前阶段，但可能阻塞正式交付。

## 交付前规则

- 项目检查器的 `N 错误` 徽标必须为 0（不出现）。
- `N 警告` 徽标必须逐条说明：已处理 / 阶段性接受 / 等待人类确认。
- 关键资产不能只通过 ID 识别，必须能通过中文标题、entity 或项目引用理解其身份。
- 证据引用优先级：CDP DOM 取证结果 > 截图路径 > 项目检查器目测 > report 文本。

## Output Format 新增字段

```markdown
## 前端可读性
- 工作台中显示名称：
- 是否仍显示未分类/未知：
- 项目检查器徽标（错误/警告）：
- 人类是否能理解用途：
- 需补动作：
```

## 禁止项

- 禁止让关键生产资产在前端只显示裸 ID 或"未分类角色"。
- 禁止把前端 warning 徽标当成无意义噪音；必须判断它是否影响生成、审片或交付。
- 禁止只在注释里写复杂说明，却不建立 entity link，导致前端无法汇总身份。

## 适用边界

本规范不要求所有临时素材立即完成 taxonomy。但只要资产进入项目引用、画布生成、审片或交付检查，就必须满足前端可读性门槛。
